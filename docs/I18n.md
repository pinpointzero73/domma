# i18n - translations

`Domma.i18n` holds your messages, picks the right plural, fills placeholders and formats numbers,
money, dates and lists for the reader's language. `Domma.t()` is the shortcut for the call you make
most. Everything locale-specific comes from the browser's `Intl`, so the module ships no data
tables.

```javascript
const {i18n} = Domma;

i18n.add('en', {
    greeting: 'Hello, {name}!',
    cart: {items: {'=0': 'Your cart is empty', one: '{count} item', other: '{count} items'}}
});
i18n.add('fr', {
    greeting: 'Bonjour, {name} !',
    cart: {items: {'=0': 'Votre panier est vide', one: '{count} article', other: '{count} articles'}}
});
i18n.fallback('en');
i18n.locale('fr');

Domma.t('greeting', {name: 'Ann'});      // "Bonjour, Ann !"
Domma.t('cart.items', {count: 3});       // "3 articles"
i18n.currency(9.5, 'EUR');               // "9,50 €"
```

## Messages

- `i18n.add(locale, messages)` - nested objects become dot keys (`cart.items`). Adding again
  **merges**: a key already there is replaced, every other key stays.
- `i18n.load(locale, source, {reload})` - `source` is a URL (fetched with `H.get`; `{locale}` in it
  is replaced with the code) or a function `(locale) => Promise<messages>`. The result is cached and
  a load already under way is shared, so three callers make one request. A failed load is not
  cached, so calling again retries. `reload: true` fetches again. When the locale on screen (or one
  of its fallbacks) finishes loading, the page is translated again.
- `i18n.has(key, {locale})`, `i18n.locales()`.

```javascript
await i18n.load('de', '/lang/{locale}.json');
i18n.locale('de');
```

## Locale and fallback

- `i18n.locale()` returns the current locale (`'en'` until you set one). `i18n.locale('fr-CA')`
  sets it: the code is canonicalised (`fr_ca` -> `fr-CA`, nonsense throws a `RangeError`), the
  `change` event fires, `<html lang dir>` are set, and `translate()` runs over the document. Setting
  the same locale again does nothing.
- `i18n.fallback('en')` or `i18n.fallback(['de', 'en'])` - searched after the current locale.
- A key is looked up in the locale, then its parent language, then each fallback and its parent:
  `fr-CA` -> `fr` -> `en`.
- `i18n.dir(code?)` - `'rtl'` or `'ltr'`, from `Intl.Locale` text info where the engine has it,
  otherwise a list of right-to-left languages and scripts (`ar`, `he`, `fa`, `ur`, `pa-Arab`...).

## Placeholders and escaping

`{name}` is replaced with `params.name`; `{user.name}` reads nested params. A placeholder with no
param is left as written, so the gap is visible rather than silently empty.

**Nothing in a message is ever evaluated.** A placeholder is looked up and replaced with its text,
and that is all - no expressions, no functions, no template literals.

| Call | Returns | Params | Message markup |
|------|---------|--------|----------------|
| `i18n.t(key, params, opts)` / `Domma.t()` | plain text | as they are | as it is (it is text) |
| `i18n.html(key, params, opts)` | HTML | escaped (`escapeHtml`) | kept |

Put `t()` into `textContent` (or `$(el).text()`); put `html()` into `innerHTML` only through the
sanitiser, as `translate()` does for `data-i18n-html`. `html()` trusts the message itself - it is
your text - and distrusts the params, which are usually somebody else's.

Options: `{locale}` translates in another locale for one call, `{default}` is returned (and
interpolated) when the key is missing, `{ordinal: true}` uses ordinal plural rules.

## Plurals and select

A plural is an **object of forms** chosen by `params.count`:

```javascript
i18n.add('pl', {files: {one: '{count} plik', few: '{count} pliki', many: '{count} plików', other: '{count} pliku'}});
i18n.t('files', {count: 22}, {locale: 'pl'});   // "22 pliki"
```

- Categories are `zero`, `one`, `two`, `few`, `many`, `other` - whichever the language uses,
  decided by `Intl.PluralRules` for the locale the message was found in. `other` is required.
- `=0`, `=1`, `=42` match a count exactly and win over the category.
- `zero` also matches a count of 0 in languages (like English) whose rules have no zero category.
- Ordinals: `ordinal: true` in the message, or `{ordinal: true}` in the options.

```javascript
i18n.add('en', {place: {ordinal: true, one: '{count}st', two: '{count}nd', few: '{count}rd', other: '{count}th'}});
i18n.t('place', {count: 22});   // "22nd"
```

A **select** names its param and picks the form whose key is that param's value, `other` otherwise:

```javascript
i18n.add('en', {reply: {select: 'gender', female: 'She replied', male: 'He replied', other: 'They replied'}});
```

**Why objects and not ICU MessageFormat.** They are already JSON, so translators and tools edit them
without learning a grammar; there is nothing to parse at run time, so no parser to ship or to get
wrong; and each form is an ordinary string with ordinary `{name}` placeholders. The price is that a
plural cannot sit in the middle of a sentence - write the whole sentence in each form, which reads
better to translators anyway.

An object counts as forms when it has a `select` string, or an `other` string and nothing but plural
categories, `=N` keys and `ordinal`. Anything else is a namespace, so `{menu: {one: 'First', extra:
'...'}}` stays two keys.

## Missing keys

A missing key returns `default` if given, else the key itself (so the page shows `cart.items`
rather than nothing). Each miss:

- fires the `missing` event `{key, locale}`;
- calls the `i18n.onMissing((key, locale) => ...)` hook - a string it returns is used as the
  translation (`i18n.onMissing(null)` removes it);
- warns in the console **once** per key and locale. `window.DommaOptions = {i18nWarnings: false}`
  before Domma loads silences the warnings.

## Formatting

All use the current locale; pass `{locale: 'de'}` in the options to format for another. Intl
instances are cached per locale + options, so formatting in a loop is cheap.

| Call | Uses | Example |
|------|------|---------|
| `i18n.number(n, opts)` | `Intl.NumberFormat` | `i18n.number(0.25, {style: 'percent'})` -> "25%" |
| `i18n.currency(n, code, opts)` | `Intl.NumberFormat` | `i18n.currency(9.5, 'GBP')` -> "£9.50" |
| `i18n.date(d, opts)` | `Intl.DateTimeFormat` | `i18n.date(D(), {dateStyle: 'long'})` |
| `i18n.relative(value, unit, opts)` | `Intl.RelativeTimeFormat` | `i18n.relative(-1, 'day', {numeric: 'auto'})` -> "yesterday" |
| `i18n.list(items, opts)` | `Intl.ListFormat` | `i18n.list(['a', 'b', 'c'])` -> "a, b, and c" |

`date()` accepts a `Date`, a timestamp, a date string or a `D()` wrapper; an invalid date formats as
`''`. `{count}` in a message is inserted as it is - pass `i18n.number(n)` as another param if you
want it grouped (`{count: n, shown: i18n.number(n)}`).

## The DOM

```html
<h1 data-i18n="home.title">Welcome</h1>
<p data-i18n="cart.items" data-i18n-params='{"count": 3}'></p>
<p data-i18n-html="legal.terms"></p>
<input data-i18n-attr="placeholder:search.placeholder; title:search.hint">
```

`i18n.translate(root = document)` fills:

- `[data-i18n="key"]` - `textContent`;
- `[data-i18n-html="key"]` - `innerHTML`, through `html()` and then the sanitiser (DOMPurify when
  loaded), so neither the message nor a param can add script;
- `[data-i18n-attr="attr:key; attr2:key2"]` - attributes;
- params for all three come from `data-i18n-params` (JSON; invalid JSON is ignored with a warning).

What the page said first is remembered, and shown again when a key is missing in the new locale -
so the authored text doubles as the default. `root` can be an element (included itself if it
carries a `data-i18n*` attribute), a selector or a Domma collection, and the return value is the
number of elements translated.

`locale(code)` translates the whole document; content you add later is translated with
`i18n.translate(el)`. There is no MutationObserver, on purpose: one would cost every page that uses
Domma, and content you build yourself is usually better built with `t()` in the first place.

## Detecting the locale

```javascript
i18n.detect({from: ['storage', 'navigator', 'html'], storageKey: 'lang', supported: ['en', 'fr', 'de'], fallback: 'en'});
```

Tries each source in order - `storage` (`S.get(storageKey)`), `navigator` (`navigator.languages`),
`html` (`<html lang>`) - and sets and returns the first acceptable locale. With `supported`, only
those count, matching on the base language too (`de-AT` -> `de`). With nothing found it uses
`fallback`, or keeps the current locale. With `storageKey`, the choice and every later
`locale(code)` are saved with `S`. `apply: false` returns the locale without setting it.

## Events

`i18n.on('change' | 'missing' | 'loaded', fn)` returns an unsubscribe function; `i18n.off(event,
fn?)` removes one (or, with no fn, all). The same events are dispatched on `document` as
`dm:i18n:change`, `dm:i18n:missing` and `dm:i18n:loaded` with the payload in `event.detail`:

| Event | Detail |
|-------|--------|
| `change` | `{locale, previous}` |
| `missing` | `{key, locale}` |
| `loaded` | `{locale, messages}` |

## Node and testing

Importing the module touches neither `window` nor `document`; `translate()` returns 0 without a
DOM, and messages, plurals and formatting all work in Node. `i18n.reset()` forgets every message,
load, listener, hook and setting - useful between tests.
